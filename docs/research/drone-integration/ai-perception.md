## Summary

- Analyst's read: Use a hybrid pipeline. Keep capture-time quality checks, privacy filtering, and urgent candidate alerts on the drone only if SDP can access DJI's Matrice 4 model-deployment programme; run paired-image processing on a local edge server after landing; use cloud models only for selected, redacted crops.
- DJI documents custom algorithms on Matrice 4 through its Intelligent Computing Platform and developer permission. Dock 3's published “Edge Computing” entry only says it supports data communication with external switches; DJI does not document the dock itself as an inference server. [DJI Intelligent Computing Platform](https://developer.dji.com/ai-developer/), [DJI Dock 3 specifications](https://enterprise.dji.com/dock-3/specs)
- Analyst's read: General-purpose vision models are weak evidence for small aerial defects. A 2026 aerial-image preprint reports the best tested open-vocabulary detector, OWLv2, at 27.6 F1 with a 69% false-positive rate; this is a warning about transfer, not a Safe Edge performance estimate. [Aerial open-vocabulary evaluation](https://arxiv.org/abs/2601.22164)
- SNIPPET-ONLY: DJI FlightHub 2 release-note search text describes media-file change detection for photos from two media folders produced by the same waypoint route, plus model change detection between overlapping 2D models. The release-note and model-change pages did not render for direct reading in this check, so equipment compatibility and Change Detection Pro claims remain unverified. Safe Edge should distinguish itself through a water-edge asset inventory, human-owned work queue, and independent repair re-test. [DJI FlightHub 2 release notes](https://fh.dji.com/user-manual/en/release-notes/release-notes-public.html), [Model Change Detection](https://fh.dji.com/user-manual/en/model-library/model-change-detection.html)
- Analyst's read: A detector cannot prove that an expected object is absent. Safe Edge needs a per-segment baseline inventory and paired views to flag a possibly missing panel, cover, buoy, or sign.
- Analyst's read: Public imagery can test parts of the pipeline, but it does not replace local validation. LEVIR-CD is a building-change dataset, and CUBIT-Det covers building, pavement, and bridge defects; neither is a township water-edge benchmark. [LEVIR-CD dataset](https://github.com/justchenhao/LEVIR/blob/master/README.md), [CUBIT-Det dataset](https://github.com/BenyunZhao/CUBIT)
- API image input is token-priced, so there is no single flat per-image fee. At the 17 October 2026 price snapshot, the documented examples below are below USD $0.001 per image for input tokens, before prompt and output tokens. [Claude pricing](https://platform.claude.com/docs/en/models/haiku-5-5/overview), [OpenAI pricing](https://developers.openai.com/api/docs/models/gpt-5.6-luna), [Gemini pricing](https://ai.google.dev/gemini-api/docs/pricing)

### 3. Change-detection pipeline and vegetation

1. Fix the capture geometry. Store camera pose and capture time, and use consistent flight paths, camera direction, altitude, and views. The cited DJI Terra accuracy page did not render during this check, so no centimetre-level accuracy claim is retained. Analyst's read: RTK or post-processed positions do not by themselves establish repeat-image alignment or defect accuracy. [DJI Terra photogrammetry accuracy](https://terra.dji.com/user-manual/en/accuracy-whitepaper/photogrammetry-accuracy.html)
2. Build an orthorectified view only where the scene supports it. DJI's reconstruction FAQ says changing reflections on water can cause stitching traces; insufficient photo overlap, indistinct surface features, and moving objects can leave missing reconstruction areas. It says empty areas in water reconstruction may not be avoidable. These are reconstruction warnings, not a guarantee of object-level defect accuracy. [DJI Terra reconstruction anomaly FAQ](https://repair.dji.com/help/content?customId=01700005151&documentType=&lang=en&paperDocType=ARTICLE&re=US&spaceId=17)
3. Register the current view to a stable baseline. LightGlue's repository says its code and pretrained LightGlue weights use Apache-2.0 and identifies the project as an ICCV 2023 paper. The repository notes that SuperPoint uses a separate restrictive licence, so select and review the feature extractor as well as the matcher. Match stable hardscape, fence posts, and permanent structures; estimate a transform from inliers and record residuals and visible coverage. If the same edge cannot be aligned confidently, mark the frame unreviewable and recapture instead of scoring a change. [LightGlue repository](https://github.com/cvg/LightGlue)
4. Compare registered pairs. ChangeFormer is a Siamese transformer change-detection model; its official repository includes LEVIR-CD and DSIFN-CD examples and declares MIT for the code. The official BIT implementation is older and says its code is for non-commercial research only; it lists Python 3.6 and PyTorch 1.6.0. [ChangeFormer paper](https://arxiv.org/abs/2201.01293), [ChangeFormer repository](https://github.com/wgcban/ChangeFormer), [ChangeFormer licence](https://github.com/wgcban/ChangeFormer/blob/main/LICENSE), [BIT repository](https://github.com/justchenhao/BIT_CD) Analyst's read: compare ChangeFormer as a research baseline, and do not build a commercial SDP pilot on the BIT implementation without permission.
5. Pair change masks with an asset inventory. Analyst's read: A visible-object detector can find a buoy that is present; a missing buoy needs an expected-object record for that edge segment and a comparable current view. Flag a likely absence or structural discontinuity for a human to check. A blocked grate or abnormal water level may need a ground-level view or separate sensor because aerial appearance alone can be ambiguous.
6. Keep distinct states for poor registration, occlusion, uncertain model output, and a human-confirmed issue. Analyst's read: do not expose a single model score as calibrated probability until it has been checked against local held-out cases. Poor registration or vegetation occlusion should trigger recapture or manual inspection, not a “no change” result.
7. Treat vegetation as a changing scene class. The cited 2024 IEEE review page did not render during this check, so the pack does not rely on it for claims about specific cross-domain causes of false change. Analyst's read: compare similar views and conditions, mask ordinary canopy change, track persistent edge access changes across observations, and keep vegetation occluding a fence or path in the “unknown / inspect” queue. Do not smooth away one sharp possible safety change by averaging it with older clear frames.

### 4. Human-in-the-loop review

The cited Harvard page for the 2021 “To Trust or to Think” experiment did not load in this check. Its participant count and effect claims are removed pending direct source access. The review workflow below is an Analyst's read, not a finding from that study.

Analyst's read: build one queue per asset segment, not a stream of raw frames. For each candidate, show the current and baseline image, the registered overlay, a close crop, route/pose, capture time, visible coverage, and why the model raised it. Show the model's class and score as a suggestion, not as a verdict.

Analyst's read: ask the reviewer for an initial label before revealing the model label on critical candidates. Then allow “confirm,” “reject,” “uncertain,” or “recapture,” with a short reason for a rejection or override. Send high-impact candidates to a second reviewer. Keep a randomized sample of unflagged segments and blinded, real test photos in periodic audits so the team can find omissions as well as false alarms. Use only real photos for seeded items; do not fabricate hazards.

Analyst's read: send reviewer corrections into an active-learning queue, but keep a separate locked evaluation set out of training. Track missed issues, false alerts, reasons for overrides, reviewer agreement, and review time.

For a locked critical-defect set, require no missed critical examples before enabling auto-prioritization; any miss should return the affected class to full human review. This gate is a pilot proposal, not evidence that the population risk is zero.

### 6. Privacy inside the pipeline

Ultralytics YOLO26 can run locally for person detection. Its code and trained models default to AGPL-3.0. Ultralytics says private or commercial deployment without meeting the AGPL disclosure terms requires an Enterprise licence; the AGPL route requires open-sourcing the full project as described in its licensing guidance. [Ultralytics YOLO26 documentation](https://docs.ultralytics.com/models/yolo26), [Ultralytics licence terms](https://www.ultralytics.com/license) SAM 2 can refine a person mask after a detector prompt, but it needs a prompt and is not a person detector by itself. [SAM 2 repository](https://github.com/facebookresearch/sam2)

Analyst's read: run person detection in memory on the aircraft if the approved DJI runtime supports it, or on a secured local edge computer immediately after capture. Blur the full person region, not just the face, before saving or uploading evidence. If the person mask is uncertain, discard that frame or store only a redacted crop with a privacy reviewer check. Retain raw imagery only if SDP has a defined incident purpose, access owner, and retention rule.

The cited 2015 Personal Data Protection Standard page did not return readable content in this check, so its deletion and security wording is not repeated here. The 2025 DPO registration manual says a controller or processor must appoint a DPO if any listed condition applies, including regular and systematic monitoring of personal data. Analyst's read: ask SDP's privacy lead whether repeated patrol imagery meets that test. The 2025 cross-border guideline says Section 129 regulates transfers of personal data outside Malaysia. [DPO registration manual, 2025](https://www.pdp.gov.my/ppdpv1/wp-content/uploads/2025/07/Manual_Pengguna_Pendaftaran_DPO_EN.pdf), [Cross-border transfer guideline, 2025](https://www.pdp.gov.my/ppdpv1/wp-content/uploads/2025/08/GP_CBPDT_EN.pdf)

Google's Gemini pricing page says free-tier content may be used to improve its products, while paid-tier content is not used for that purpose. [Gemini API pricing and data-use terms](https://ai.google.dev/gemini-api/docs/pricing) Analyst's read: use only the paid tier for any permitted VLM test, and send redacted crops only after SDP has reviewed the provider's data-processing and transfer terms.

### 7. What can be real in the hackathon demo

Sime Darby Property's 25 October 2024 press release identifies Elmina Central Park as the central park of the City of Elmina township. [Sime Darby Property, “Fuses Art, Nature, and Sustainability,” 25 October 2024](https://www.simedarbyproperty.com/press-releases/sime-darby-property-fuses-art-nature-and-sustainability)

Sime Darby Property's hackathon page lists proposal submission on 23 October 2026 and judging from 24–28 October. It names Safety and security under the People theme. The judging weights are impact and sustainability 25%, innovation 20%, feasibility 20%, strategic fit 15%, commercial value 10%, and team/evidence/pitch quality 10%. The page says prototypes should demonstrate a solution in a real township environment. [Township of Tomorrow hackathon](https://www.simedarbyproperty.com/universityhackathon/)

Analyst's read: make the site imagery real. Use a current team-captured Elmina photo and, if available, a second real photo from the same viewpoint. Obtain park-owner permission, avoid capturing identifiable people where possible, and apply local redaction before storing the image. Run a hosted VLM on a real redacted crop only as a draft caption or candidate explanation. If there is no comparable baseline, label the result “single-image observation; change not evaluated.”

Analyst's read: the patrol path, drone animation, queue transitions, Fix Lens barrier, work-order state, and repair re-test can be scripted in the 3D simulation. Label each as simulated. Do not show an invented gap, missing buoy, repair, or AI alert as if it came from a real site observation. If the team has no permitted drone approval, use ground photos or public licensed real imagery and say so.

CAAM says Standard Authorisation to Fly (ATF) applications are due at least 14 working days before the operation. Standard ATF covers low-risk flights within VLOS or EVLOS (up to one visual observer), without spraying or dispensing, and below 400 ft AGL unless ATC approves otherwise. CAAM also says applicants should contact other agencies before filing ATF; its page lists JUPEM approval for UAS able to do surveillance or measurement such as aerial photography and mapping. CAAM's application guidance asks for a Google Earth Pro flight plan saved as `.kmz` or `.kml` with activity, geofencing, risk, and boundary zones. Analyst's read: confirm with CAAM, JUPEM, and SDP which approvals apply to the planned site flight. [CAAM UAS guidance](https://www.caam.gov.my/public/unmanned-aircraft-system-uas/), [CAAM UAS guidance in Malay](https://www.caam.gov.my/bm/sumber/profesional-penerbangan/sistem-pesawat-tanpa-pemandu-uas/) Analyst's read: use ground-captured imagery unless the needed flight and agency approvals are already in place.

### 8. Recommended architecture, evaluation, and demo plan

Analyst's read: use this staged flow:

1. **Asset and baseline registry.** Give each water-edge segment a stable ID, owner, expected barrier/cover/sign/buoy inventory, approved viewpoints, and last human-accepted baseline. Store the baseline with its capture conditions and reviewer.
2. **Capture and privacy gate.** Run the mission after conditions permit flight. Check image sharpness, coverage, pose, and people. Blur people in memory before storage; discard frames that cannot be redacted reliably.
3. **Registration gate.** Align each current view to its matching baseline using stable hardscape and feature matches. Save alignment residuals and visibility. Poor alignment, missing coverage, reflections, or heavy occlusion become “unreviewable / recapture.”
4. **Candidate generation.** Compare the registered pair with a local change model and class detectors. Use semantic prompts for visible candidate objects, and the asset inventory for possible missing objects. Use segmentation only to refine candidate regions.
5. **Confidence routing.** Keep input quality, registration quality, detection score, and class-specific calibration separate. Low quality means recapture; uncertain output means review; high-concern candidates get a priority human queue. No model output can issue an “edge safe” pass.
6. **Human decision and work record.** Show before/current evidence and independent reviewer input. Let the maintenance owner accept, reject, request another view, or draft a work order. A work order is not closed until a separate post-repair image is reviewed.
7. **Learning and audit.** Add reviewed cases to a versioned training set. Keep the golden test set locked. Audit unflagged real segments and report missed events, false alerts, and uncertainty by asset and capture condition.

Analyst's read: for evaluation, start with LEVIR-CD for paired-image code flow, CUBIT-Det for real infrastructure crops, and a permission-cleared local Elmina set for all launch decisions. Report critical-event recall first, then false alerts per segment/patrol, precision, localization, calibration, reviewer agreement, and recapture rate. A public-dataset score should never be presented as Safe Edge accuracy.

Analyst's read: for the demo, show one real, redacted site image and an actual model response; show the route, alert lifecycle, Fix Lens, work order, and re-test as labeled simulation. If no authentic water-edge change has been verified, demonstrate candidate review on a real normal scene and say the defect detector remains unvalidated.

## Recommendations for Safe Edge

1. Analyst's read: (Finding 1) Use a township edge server as the first full-resolution inference target; keep only an onboard capture-quality/privacy gate until SDP confirms DJI model access, accepted formats, and deployment terms.
2. Analyst's read: (Findings 2 and 3) Treat open-vocabulary models as proposal generators. Pair them with a per-segment expected-object inventory, repeatable viewpoints, and a registration quality gate.
3. Analyst's read: (Findings 4 and 5) Require independent human review of critical candidates, preserve unflagged samples for audits, and tune thresholds against a locked local golden set.
4. Analyst's read: (Finding 6) Redact or discard people before persistent storage and before any provider request. Get SDP privacy approval for repeated monitoring and any cross-border processing.
5. Analyst's read: (Findings 7 and 8) Keep real site evidence separate from simulated workflow states. Pitch the demo as a real-image perception prototype with a simulated operational loop, not a proven inspection service.

## What we can and cannot claim

### Safe claims

- Analyst's read: “The prototype compares a real, redacted site photo against a baseline and raises a candidate for human review.” Use only if the shown pair is real and the model actually produced that output.
- Analyst's read: “The demo simulates patrol routing, maintenance triage, Fix Lens, and independent repair re-test.” Label each simulated state in the interface.
- Analyst's read: “Safe Edge is designed to keep the AI advisory: it can flag, draft, and request review.” This matches the proposed human approval flow; it is not a claim of field accuracy.

### Claims to avoid

- “Safe Edge prevents drowning,” “certifies an edge as safe,” or “catches every defect.” No cited study validates these outcomes, and the listed aerial/infra results show material domain-transfer limits.
- “The model found a real missing panel/buoy/cover” when the image is staged, simulated, or lacks verified site ground truth.
- “The system is accurate because it scores well on LEVIR-CD, COCO, DIOR, or CUBIT-Det.” Those benchmarks do not cover township water-edge hazards.
- “AI knows the water level is abnormal” from an uncalibrated aerial photo. Water reflections and surface texture can impair reconstruction, and no calibrated water-level sensor is part of this perception pipeline.
